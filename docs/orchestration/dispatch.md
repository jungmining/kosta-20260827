# `/dispatch`: 동적 단일 위임

[실행 원본](../../.claude/commands/dispatch.md) · [dispatcher 원본](../../.claude/agents/dispatcher.md)

## 목적

요청의 성격을 먼저 판단하고, 허용된 담당자 하나에게 과제를 한 번만 맡긴다.

## 선택 규칙

| 요청 성격 | 담당 |
|---|---|
| 새 기능·동작 변경 | `implementer` |
| 테스트만 필요 | `tester` |
| 판단·평가만 필요 | `reviewer` |
| 요구가 모호함 | `requirements-analyst` |

## 실행 단계

1. `dispatcher`가 담당자를 선택한다.
2. `담당:` 값이 허용된 이름 하나인지 검증한다.
3. 선택된 담당자에게 사용자의 원문 과제를 변경 없이 정확히 한 번 전달한다.
4. 결과를 그대로 보고한다.

## 가드레일

- 복수 담당·보조 담당·후속 담당을 지정하지 않는다.
- 병렬 실행이나 재배정을 하지 않는다.
- `/handoff`, `/pipeline`, `/parallel-check`, `/agents-review`를 후속 실행하지 않는다.
- 결과가 부족하거나 실패해도 다른 에이전트를 추가하지 않는다.
- 배정 결과가 허용 목록과 정확히 일치하지 않으면 담당자를 호출하지 않고 오류만 보고한다.

`dispatcher` 출력은 다음 두 줄이어야 한다.

```text
담당: <허용된 이름 하나>
근거: <한 줄>
```

## 실행 원본의 주의사항

`dispatch`는 `pipeline`이나 `parallel-check`를 조합하는 명령이 아니라 의도적으로 단일 에이전트만 호출하는 독립 흐름이다.
